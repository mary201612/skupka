## Часть 2. Обновление серверного скрипта (заявки)

> ⚠️ **Главное правило:** не создавайте «New deployment». Меняйте существующий деплой,
> иначе изменится URL и сайт перестанет доставлять заявки.

### 2.1. Откройте проект скрипта
1. Зайдите на https://script.google.com
2. Откройте проект, который обслуживает `skupaishop.ru`
   (в нём уже есть функция `doPost` — это и есть приёмник заявок)

### 2.2. Вставьте новый код
1. Полностью замените содержимое файла `Code.gs` на содержимое `apps_script.gs`
2. **Проверьте блок `CONFIG` в начале:**
   - `BOT_TOKEN` — токен вашего бота. В архиве подставлен токен из `send.php`
     (`9006346767:AAE9…`). **Если в текущем скрипте токен другой — оставьте текущий!**
   - `CHAT_ID` — чат, куда приходят заявки (в архиве `733151736`).
3. Сохраните: **Ctrl+S**

### 2.3. Резервное сохранение в Google Таблицу — ✅ УЖЕ НАСТРОЕНО
В скрипте уже вписан ID вашей таблицы:
`SHEET_ID: '1kc2U-72z_56dCETLryHaKT8uX6SD9LUq0cYgalD7rDw'`
(лист «Заявки» создастся автоматически при первой заявке).

Если понадобится другая таблица — замените ID из адресной строки:
`docs.google.com/spreadsheets/d/`**`1AbC...ЭТОТ_ID`**`/edit`

### 2.4. Копия заявки на e-mail — ✅ УЖЕ НАСТРОЕНО
`NOTIFY_EMAIL: 'lomteh1612@gmail.com'` — при первом запуске Google попросит
разрешение на отправку писем, разрешите. Чтобы отключить копии — поставьте `''`.

### 2.5. (Опционально) Дубль в группу менеджеров
Впишите: `GROUP_CHAT_ID: '-1001234567890'` (ID группы; бота нужно добавить в группу).

### 2.6. Передеплойте БЕЗ смены URL (важно: «Execute as: Me»)
1. **Deploy → Manage deployments**
2. У существующего деплоя нажмите ✏️ (карандаш)
3. **Проверьте настройки веб-приложения:**
   - **Execute as: `Me (ваш e-mail)`** — критично! Если стоит «User accessing the web app»,
     скрипт выполняется анонимно и **не имеет доступа к Google Таблице и почте**
     (Telegram при этом работает, поэтому проблема незаметна).
   - **Who has access: `Anyone`**
4. В поле **Version** выберите **New version** → **Deploy**
5. Убедитесь, что URL остался прежним
6. При первом запуске Google покажет экран разрешений:
   **Advanced → Go to … (unsafe) → Allow**

### 2.7. Проверьте, что всё работает
В редакторе скрипта выберите функцию в выпадающем списке и нажмите **Run**:

| Функция | Что делает |
|---|---|
| `checkTelegram()` | Проверяет токен (`getMe`), чат (`getChat`), таблицу и e-mail. Результат — в **Execution log** |
| `sendTestLead()` | Отправляет тестовую заявку во все каналы |

Затем проверьте само здоровье endpoint — откройте в браузере URL деплоя:
```
https://script.google.com/macros/s/.../exec
```
Должно вернуться примерно:
```json
{"ok":true,"service":"skupka74-lead-endpoint","version":"v4-telegram-sheet-email",
 "token_ok":true,"chat_set":true,"sheet_set":true,"email_set":false}
```

И финальная проверка — отправьте заявку с сайта (заполните форму на skupaishop.ru).

### 2.8. Диагностика (если что-то не работает)
Откройте в браузере (подставьте свой URL деплоя):
```
https://script.google.com/macros/s/.../exec?diag=skupka-diag-7f3a91
```
В ответе появится блок `diag`:
- `effective_user` — от чьего имени выполняется скрипт (должен быть ваш e-mail, не «(аноним)»);
- `telegram`, `sheet`, `email` — статус последнего канала и текст ошибки, если он не сработал.

Если `effective_user` = `(аноним)` — значит в деплое стоит «Execute as: User accessing the web app»,
исправьте на «Me» (см. п. 2.6).

## Часть 3. Антиспам

В скрипте уже работают:
- **honeypot** — скрытое поле `website_url`; боты его заполняют, заявка тихо отбрасывается;
- **лимит на номер** — не более 3 заявок в сутки с одного телефона;
- **общий лимит** — не более 400 заявок в сутки на весь скрипт;
- **защита от дублей** — одинаковый телефон + техника в течение 10 минут отбрасывается.

Настройки — в `CONFIG`: `MAX_PER_PHONE_PER_DAY`, `MAX_TOTAL_PER_DAY`, `DEDUP_MINUTES`.

Если пойдёт настоящий спам — добавьте Яндекс SmartCaptcha (понадобится ключ и правка формы).

## Часть 4. Безопасность: токен бота

В файле `send.php` (в папке проекта) лежит **живой токен бота**. На GitHub Pages PHP
не работает, файл не нужен — он в `.gitignore` и в репозиторий не попадает.

Рекомендации:
1. **Удалите `send.php`** из папки проекта (или перенесите в защищённое место).
2. Если файл куда-то отправляли (хостинг, мессенджер, архив) — **перевыпустите токен**
   у @BotFather: `/mybots` → ваш бот → **API Token** → **Revoke current token**.
   После этого обновите `BOT_TOKEN` в Apps Script и передеплойте.
3. Никогда не публикуйте `.env`, `send.php`, ключи и пароли в репозитории.

## Часть 5. Если URL деплоя всё-таки изменился

Тогда заявки «уйдут в никуда». Исправляется так:
1. Скопируйте новый URL деплоя
2. В `index.html` найдите строку `const LEAD_ENDPOINT = '...'` (≈ строка 2700)
3. Замените значение на новый URL
4. Загрузите `index.html` на GitHub (Часть 1.2)

Проверка: откройте `https://skupaishop.ru/`, отправьте тестовую заявку.
